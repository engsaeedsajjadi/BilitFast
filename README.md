# Bilit Fast — نسخه تحت وب (Vercel / serverless)

تبدیل برنامه دسکتاپی **BilitFast.py** (PyQt5 / ویندوز) به یک وب‌اپ **serverless** برای استقرار روی **Vercel**، با حفظ منطق اصلی.

بک‌اند به **Node.js** بازنویسی شده است (توابع serverless در پوشه `api/`)، چون Vercel
توابع Node را به‌صورت native اجرا می‌کند و پایتون/Flask را به‌صورت سرور طولانی‌مدت اجرا نمی‌کند.

## تغییرات انجام‌شده نسبت به نسخه دسکتاپ

| بخش | نسخه دسکتاپ (ویندوز) | نسخه تحت وب (Vercel) |
|---|---|---|
| رابط کاربری | PyQt5 | HTML/CSS/JS (RTL، فارسی) |
| بک‌اند | پایتون + PyQt5 | Node.js (توابع serverless) |
| دوره آزمایشی | رجیستری ویندوز (`winreg`) | `localStorage` مرورگر |
| ذخیره وضعیت مسیرها | `QSettings` | `localStorage` مرورگر |
| ورود به سامانه | خواندن کوکی Firefox (`browser_cookie3`) | صفحه ورود داخلی + ذخیره کوکی |
| رزرو نهایی | بازکردن Firefox + چسباندن خودکار (`pyautogui`) | جریان چندمرحله‌ای سمت سرور: کپچا → تکمیل خودکار مسافر → هدایت به پرداخت |
| حلقه جستجو | `QThreadPool` (ترد پس‌زمینه) | polling سمت مرورگر |

**منطق بدون تغییر** (پورت مستقیم از `BilitFast.py`):
- ساخت داده جستجو (`_build_search_data` → `buildSearchData`)
- استخراج قطارها با سِلکتورهای `config.json` (`extract_trains`؛ با cheerio به‌جای lxml)
- ساخت فرم رزرو HTML (POST به `TresV.php`)
- محدودسازی/ساختار درخواست، نگاشت جنسیت، شمارش مسافران بر اساس سهمیه

## چرا معماری تغییر کرد؟

Vercel محیط **serverless** است: هر تابع بعد از پاسخ دادن به HTTP فریز می‌شود و
فایل‌سیستم آن فقط‌خواندنی/موقتی است. بنابراین دو تفاوت ضروری ایجاد شد:

1. **حلقه جستجو** به مرورگر منتقل شد: مرورگر هر ۳ ثانیه یک بار `POST /api/search` می‌زند
   (هر درخواست = یک تلاش). نتیجه همان «جستجو تا یافتن قطار» است، بدون نیاز به ترد سمت سرور.
2. **وضعیت** (دوره آزمایشی، مسیرها، کوکی‌ها) در `localStorage` مرورگر نگهداری می‌شود،
   نه در فایل/رجیستری.

## ساختار

```
api/
  search.js     ← یک تلاش جستجو (POST به searchWagn.php + استخراج قطارها)
  reserve.js    ← جریان چندمرحله‌ای رزرو (شروع / ارسال کپچا و اطلاعات / تصویر کپچا)
  login.js      ← ورود به سامانه و بازگرداندن کوکی‌ها
  cities.js     ← لیست شهرها
  config.js     ← نمایش تنظیمات
  sync-cookies.js ← همگام‌سازی کوکی از Firefox/Chrome
lib/
  core.js       ← منطق اصلی (پورت از BilitFast.py)
  reserve.js    ← جریان رزرو (کپچا، فرم مسافر، هدایت به پرداخت) — بدون حالت (stateless)
  captcha.js    ← حل خودکار کپچا (پیش‌پردازش تصویر + OCR با tesseract.js)
  cookies.js    ← خواندن کوکی Firefox (cookies.sqlite)
  chrome-cookies.js ← رمزگشایی کوکی Chrome (DPAPI/Keychain/peanuts)
public/
  index.html    ← فهرست مسیرها
  route.html    ← فرم مسیر + مسافران + جستجو + رزرو
  login.html, trial.html, settings.html
  app.js        ← منطق کلاینت (وضعیت، دوره آزمایشی، تاریخ شمسی، polling)
  style.css
  jalaali.min.js ← تبدیل تاریخ شمسی (jalaali-js)
config.json     ← تنظیمات (سِلکتورها، آدرس‌ها، فیلدهای ورود)
cities.json     ← کد شهرها
package.json, vercel.json, dev-server.js
BilitFast.py    ← کد اصلی دسکتاپی (مرجع، بدون تغییر)
```

## اجرای محلی

```bash
npm install
node dev-server.js     # http://localhost:3000
```

## ⚠️ نکته مهم درباره اجرا روی Vercel (و هر هاست خارجی)

سایت صفیر ریل (`safirrail.ir`) درخواست‌های ارسال‌شده از **IPهای خارجی/دیتاسنتر**
(مانند سرورهای Vercel که در آمریکا/اروپا هستند) را در سطح شبکه مسدود می‌کند. نتیجه این
است که تابع جستجو (`/api/search`) با خطای **`fetch failed`** مواجه می‌شود و نمی‌تواند
به سایت وصل شود.

به همین دلیل، **جستجوی واقعی روی Vercel کار نمی‌کند**. برنامه دسکتاپی اصلی هم دقیقاً
به همین دلیل روی سیستم خودِ کاربر اجرا می‌شد (با IP و کوکی‌های محلی).

### راه‌حل درست: اجرای محلی

```bash
npm install
npm start          # معادل node dev-server.js
```

سپس در مرورگر: http://localhost:3000

چون سرور روی سیستم خودتان اجرا می‌شود، درخواست جستجو با IP محلی شما ارسال می‌شود و
به سایت صفیر ریل می‌رسد — دقیقاً مثل نسخه دسکتاپی.

### اگر همچنان می‌خواهید به‌صورت آنلاین اجرا کنید
بک‌اند (پوشه `api/` و `lib/`) را روی یک **سرور/هاست ایرانی** یا هر جایی که به
`safirrail.ir` دسترسی شبکه دارد، اجرا کنید و فرانت‌اند (`public/`) را همان‌جا سرو کنید.

## استقرار روی Vercel

1. ریپو را در Vercel import کنید.
2. چارچوب (framework) به‌صورت خودکار شناسایی می‌شود (Node.js + `api/` functions + `public/` static).
3. **Build & Development Settings**: اگر لازم شد، دستور build را «None» و output را «public» بگذارید؛
   یا از تنظیمات پیش‌فرض Vercel برای پروژه‌های بدون build استفاده کنید.
4. Deploy کنید.

> نکته: Vercel فقط برنچ `main` را به‌صورت production deploy می‌کند (یا برنچی که در
> dashboard انتخاب کرده‌اید). مطمئن شوید کد وب روی برنچ درست قرار دارد.

## نکات مهم

### ۱. ورود به سامانه (همگام‌سازی کوکی)
بهترین راه ورود، دکمه‌های **«همگام‌سازی کوکی از Firefox / Chrome»** در صفحه `/login.html` است.
این دکمه‌ها کوکی‌های دامنه `safirrail.ir` را مستقیماً از پروفایل مرورگر سیستم شما
می‌خوانند و به برنامه منتقل می‌کنند — دقیقاً همان کاری که نسخه دسکتاپی با
`browser_cookie3` انجام می‌داد. کافی است ابتدا در مرورگر وارد سایت صفیر ریل شوید
و سپس در برنامه روی دکمه بزنید.

- **Firefox**: کوکی‌ها به‌صورت متن ساده در `cookies.sqlite` ذخیره می‌شوند.
- **Chrome**: کوکی‌ها رمزنگاری‌شده‌اند و برنامه آن‌ها را رمزگشایی می‌کند:
  - ویندوز: کلید AES-256-GCM از `Local State` + DPAPI (از طریق PowerShell)
  - مک: کلید از Keychain «Chrome Safe Storage»
  - لینوکس: کلید ثابت «peanuts» (حالتی که keyring تنظیم نشده باشد)

> چون این کار نیاز به خواندن فایل‌های مرورگر روی سیستم شما دارد، فقط در اجرای محلی
> کار می‌کند (روی Vercel ممکن نیست). توجه: اگر Chrome در حال اجرا باشد ممکن است
> فایل کوکی‌ها قفل باشد؛ در این صورت برنامه را ببندید یا از روش جایگزین استفاده کنید.

راه جایگزین، چسباندن دستی کوکی است: در مرورگر وارد صفیر ریل شوید، در Console دستور
`document.cookie` را اجرا و خروجی را در صفحه «ورود» جای‌گذاری کنید.

همچنین صفحه ورود یک فرم ورود مستقیم (POST به سامانه) دارد؛ نام فیلدها (`user`/`pass`)
و آدرس ورود در `config.json` قابل تنظیم است:

- `login_url` — مسیر فرم ورود
- `login_action` — مقدار پارامتر `Action`
- `login_user_field` / `login_pass_field` — نام فیلدهای شناسه/گذرواژه
- `login_success_marker` — متنِ صفحه در ورود موفق (برای تشخیص)

### ۲. تنظیمات (config.json)
روی Vercel فایل‌سیستم فقط‌خواندنی است؛ بنابراین `config.json` باید در ریپو ویرایش و
دوباره دیپلوی شود. صفحه «تنظیمات» فقط نمایش‌دهنده مقادیر فعلی است.

### ۳. رزرو نهایی (چندمرحله‌ای — مثل سایت صفیر ریل)

جریان رزرو حالا همان مسیر سایت اصلی را دنبال می‌کند و توسط سرور (با کوکی‌های
همگام‌سازی‌شده) انجام می‌شود:

1. **انتخاب قطار** → سرور پارامترها را به `TresV.php` ارسال می‌کند.
2. **کپچا** → سرور صفحه کپچا را تشخیص می‌دهد، تصویر کپچا را دریافت و در برنامه
   نمایش می‌دهد. برنامه **ابتدا تلاش می‌کند کپچا را خودکار با OCR حل کند** (tesseract.js)
   و در صورت موفقیت، خودکار ادامه می‌دهد؛ اگر OCR ناموفق بود (تا ۵ تلاش)، کد امنیتی
   به کاربر نمایش داده می‌شود تا خودش تایپ کند (Human-in-the-loop).
3. **اطلاعات مسافر** → چون کاربر قبلاً مشخصات مسافران را وارد کرده، سرور آن‌ها را
   **به‌صورت خودکار** در فیلدهای فرم سایت قرار می‌دهد. نام فیلدهای واقعی سایت صفیر ریل
   (با پسوند index برای هر مسافر) در `config.json` تنظیم شده است:
   `pid{index}` (کد ملی)، `ruz{index}` (روز)، `mah{index}` (ماه)، `sal{index}` (سال)،
   `fn{index}` (نام)، `ln{index}` (نام خانوادگی)، و `phone` (شماره همراه مشترک).
4. **تأیید و پرداخت** → سرور رزرو را تأیید می‌کند و کاربر به صفحه پرداخت هدایت می‌شود.

هر مرحله بدون حالت (stateless) است: یک «توکن وضعیت» بین مراحل ردوبدل می‌شود، بنابراین
هم روی سرور محلی و هم روی Vercel کار می‌کند.

> ⚠️ **نکته (نام فیلدها):** نام فیلدهای مسافر از ساختار واقعی سایت (`pid`/`ruz`/`mah`/
> `sal`/`fn`/`ln` با پسوند index + `phone`) در `config.json` تنظیم شده است. اگر سایت این
> نام‌ها را تغییر داد، خروجی هر مرحله یک «تشخیص» (list نام همه فیلدهای فرم) برمی‌گرداند
> تا بتوان مقادیر را با فرم واقعی هماهنگ کرد و `config.json` را به‌روز رساند.

در صورت ناموفق بودن رزرو خودکار، همچنان می‌توانید **فرم رزرو HTML** را دانلود و در
مرورگر خود (جایی که وارد صفیر ریل شده‌اید) باز کنید — روش جایگزین همان نسخه قبلی.

### ۴. امکانات جستجو
- حداکثر **۶ مسافر** قابل تعریف است (اعتبارسنجی هم در مرورگر و هم در سرور).
- جستجو هر **۳ ثانیه** یک بار انجام می‌شود تا ظرفیت مورد نظر یافت شود.
- با یافتن ظرفیت، یک **نوتیفیکیشن مرورگر** نمایش داده می‌شود (درخواست مجوز در اولین کلیک «شروع جستجو»).
- کاربر می‌تواند یا **شماره قطار** خاصی را پایش کند، یا فقط **مسیر + تاریخ** را جستجو کند.

### ۵. نکات مهم
- **حل خودکار کپچا (OCR)**: برنامه تلاش می‌کند کپچا را با tesseract.js حل کند، اما
  موفقیت آن روی متن اعوجاجی (kcaptcha) تضمینی نیست؛ در صورت شکست، کپچا به کاربر
  واگذار می‌شود. توجه: دور زدن کپچا ممکن است خلاف شرایط استفاده سایت باشد — از این
  قابلیت فقط برای رزرو بلیت خودتان و با رعایت شرایط استفاده استفاده کنید.
- **انجام خودکار پرداخت بانکی** — پرداخت شامل اطلاعات مالی کاربر است و توسط خود کاربر
  انجام می‌شود. برنامه فقط کاربر را به صفحه پرداخت هدایت می‌کند و هیچ اطلاعات کارت/
  رمز بانکی را ذخیره یا log نمی‌کند.

### ۶. توجه حقوقی/اخلاقی
این برنامه برای رزرو خودکار/مانیتورینگ ظرفیت قطار ساخته شده است. لطفاً مطابق قوانین
و شرایط استفاده سایت صفیر ریل از آن استفاده کنید و از فشار بیش از حد به سرورها پرهیز
نمایید.
