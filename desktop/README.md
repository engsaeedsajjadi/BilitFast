# نسخه دسکتاپ ویندوز (BilitFast.exe)

این پوشه برنامه را به یک فایل نصبی/قابل‌حمل ویندوز تبدیل می‌کند (Electron).
سرور Node **داخل خود exe** اجرا می‌شود، پس کاربر نهایی به نصب Node.js نیازی
ندارد.

## قابلیت نشانه نصب (ضد دور زدن دوره آزمایشی)

در اولین اجرای برنامه روی هر کامپیوتر:

1. شناسه دستگاه از روی `MachineGuid` ویندوز + شماره سریال دیسک + نام ماشین ساخته می‌شود.
2. تاریخ نصب (امروز) و شناسه دستگاه در رجیستری زیر این کلید نوشته می‌شود:
   ```
   HKCU\Software\BilitFast
     InstallDate        (ISO date)
     DeviceId           (هش ۳۲ کاراکتری)
     AppVersion
     InstallSignature   (امضای HMAC، ضد دستکاری)
   ```
3. یک امضای HMAC-SHA256 هم ذخیره می‌شود که با کلید مشترک سرور (`BILITFAST_INSTALL_KEY`)
   ساخته/بررسی می‌شود؛ کاربر نمی‌تواند تاریخ را دستی به عقب ببرد.

اجراهای بعدی همان رکورد خوانده می‌شود و تاریخ نصب تغییر نمی‌کند. با نصب
مجدد ویندوز یا کپی برنامه به دستگاه دیگر، شناسه دستگاه فرق می‌کند و
برنامه آن را «نصب تازه» محسوب می‌کند.

در نسخه دسکتاپ، دوره آزمایشی مهمان به همین **تاریخ نصب واقعی** گره می‌خورد
(نه تاریخِ اولین اجرای مرورگر)؛ کاربر واردشده همواره تاریخ را از سرورِ حساب
می‌خواند که قوی‌تر است.

## ساخت فایل نصبی

نیاز: Node.js 18+ روی دستگاه سازنده.

```powershell
# ۱) وابستگی‌های خود سرور را نصب کنید
npm install

# ۲) وابستگی‌های پوسته دسکتاپ را نصب کنید
cd desktop
npm install

# ۳) (پیشنهادی) کلید امضای نصب را هنگام build تزریق کنید:
$env:BILITFAST_INSTALL_KEY="<یک رشته تصادفی ۶۴ کاراکتری>"

# ۴) خروجی Setup.exe:
npm run dist
# یا نسخه قابل‌حمل (بدون نصب):
npm run dist:portable
```

خروجی‌ها در `desktop/dist/`:
- `BilitFast Setup 1.0.0.exe`  (نصاب NSIS)
- `BilitFast 1.0.0.exe`        (نسخه portable)

نکته: در نسخه نهایی، همان کلید `BILITFAST_INSTALL_KEY` روی محیطی که
`npm run dist` را اجرا می‌کند باید ست باشد تا امضای رجیستری با کلیدی که
سرور داخل exe بررسی می‌کند یکی باشد (در توسعه از کلید پیش‌فرض استفاده
می‌شود).

## اجرای توسعه (بدون بسته‌بندی)

```powershell
# در ریشه پروژه:
npm start
# در پنجره‌ای دیگر:
cd desktop
npm start
```
