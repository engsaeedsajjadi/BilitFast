# BilitFast Web 3.10.0 — اتصال مستقیم نشست مرورگر

## چرا روش قبلی به بن‌بست می‌رسید؟
در 3.9، افزونه فقط از تب BilitFast اجرا می‌شد. ابتدا کد دو‌دقیقه‌ای روی سرور تولید
و سپس کوکی با `push/poll/ack` منتقل می‌شد. قطع شبکه، جابه‌جایی تب و انقضای کد
می‌توانست کاربر را روی پیام «منتظر پاسخ» نگه دارد. استفاده از کد دوباره تضمین نمی‌کرد
که سایت اصلی نشست را می‌پذیرد.

## روش جدید — سه عمل کاربر
1. **همان پنجره/پروفایل Chrome یا Edge:** صفحه BilitFast را باز نگه دارید.
2. در تب رسمی `https://safirrail.ir/etrain/index.php` وارد حساب شوید و در **همان تب** روی افزونه کلیک کنید.
3. مقصد BilitFast نشان داده می‌شود. دامنه را بررسی و «اتصال نشست به BilitFast» را بزنید و مجوز همان دامنه را تأیید کنید.

افزونه فقط تب‌هایی با دامنه HTTPS مجاز (یا پیش‌نمایش محلی `127.0.0.1:3000` / `localhost:3000`)
و صفحه مشخص BilitFast را در همان پنجره می‌پذیرد. قبل از دسترسی به کوکی، شناسه
صفحه مقصد را بررسی می‌کند. کوکی‌های `PHPSESSID` مربوط به `/etrain` و `/fa`
با دامنه مجزای خودشان از *پروفایل کوکی همان تب رسمی* استخراج می‌شوند.
اطلاعات در حافظه تب BilitFast (`sessionStorage`) نوشته و بلافاصله بازخوانی می‌شود.
در صورت موفقیت، پل «انتخاب قطار و تأیید ربات» نصب می‌شود.

هیچ درخواست `push` به `cookie-sync`، توکن ضدربات، رمز حساب یا کد یک‌بارمصرف
در جریان **جدید** وجود ندارد. endpoint قدیمی ممکن است برای سازگاری وجود داشته باشد
اما رابط 3.10 از آن استفاده نمی‌کند.

## محدودیت‌ها و امنیت
- **این روش انتقال اعتبارنامه حساس است.** فقط با رضایت صاحب حساب و روی نصب متعلق به
  آژانس مورد اعتماد استفاده شود. اگر دامنه نمایش‌داده‌شده ناشناس است، مجوز ندهید.
- هیچ سازوکاری تضمین نمی‌کند که سرور سفیر ریل کوکی وارد‌شده در بک‌اند را از IP دیگر بپذیرد.
  درخواست رزرو رسمیِ افزونه از نشست *مرورگر* استفاده می‌کند و بهترین راه حفظ نشست است.
- `sessionStorage` به هر **تب** وابسته است. مسیرها را از همان تب BilitFast باز کنید.
- سایت رسمی ممکن است نشست را منقضی/محدود کند؛ «ذخیره شد» **معادل ورود معتبر** نیست.
- افزونه CAPTCHA را کلیک، حل یا جابه‌جا نمی‌کند و توکن نمی‌سازد یا تکرار نمی‌کند.
- اگر چند تب BilitFast باز باشد، افزونه برای جلوگیری از انتخاب مقصد اشتباه متوقف می‌شود.
- نسخه تجاری باید برای حفاظت از کوکی‌ها در برابر XSS، کنترل دسترسی کاربر و مدیریت بک‌اند بررسی شود.

## تست‌ها
```powershell
npm ci
npm run test:web-extension
npm run test:official-handoff
npm test
npm run preview:web
```

نسخه افزونه در `chrome://extensions` باید **3.10.0** باشد و نسخه‌های قدیمی غیرفعال باشند.
اول در محیط آزمایشی و با حساب مجاز تست کنید؛ هرگز کوکی یا آدرس بانکی حاوی Token را در گزارش عمومی قرار ندهید.
