# اصلاح توقف روی انتخاب قطار — BilitFast 3.11.0

## ریشه مشکل

در نسخه 3.10، پس از کلیک دکمه ردیف قطار، سرور مشتری ابتدا رزرو را از طرف خودش با کوکی منتقل‌شده آغاز می‌کرد؛ تنها وقتی سایت `arcaptcha_required` را به سرور برمی‌گرداند، افزونه مأمور جابه‌جایی تب می‌شد. پاسخ ورود/شبکه/مهلت زیاد باعث می‌شد انتقال هیچ‌وقت اجرا نشود. همچنین خطای بازکردن پنل کناری Chrome، رزرو را کلاً متوقف می‌کرد.

## رفتار جدید

1. کاربر اطلاعات مسافر و قطار را از قبل در BilitFast ثبت می‌کند.
2. افزونه روی همان تب، آماده‌بودن پل انتخاب قطار را اعلام می‌کند.
3. API محلی فقط فیلدهای رزرو را با استفاده از `buildReserveForm` و `buildReserveInitBody` می‌سازد و مقصد `https://safirrail.ir/etrain/TresV-auth.php` را اعتبارسنجی می‌کند؛ **کوکی یا توکن کپچا از این API عبور نمی‌کند**.
4. افزونه پس از دریافت فرم آماده، همان تب را به `https://safirrail.ir/etrain/index.php` می‌برد و فرم رسمی را از همان دامنه POST می‌کند. کوکی‌های ورود را مرورگر به درخواست رسمی اضافه می‌کند.
5. ARCaptcha باید توسط **خود کاربر** تأیید شود؛ در صورت موفقیت سایت رسمی، ادامه معمول مسافر/کوپه فقط در محدوده کنترل‌های شناخته‌شده انجام می‌شود.
6. شکست در بازکردن پنل کناری جلوی انتقال به سایت اصلی را نمی‌گیرد. در صورت نیاز کاربر پنل را دستی باز می‌کند.

## تست با Chrome

- `npm ci`
- `npm run test:selection-regression`
- `npm run test:official-handoff`
- `npm run preview:web`
- افزونه قدیمی را در `chrome://extensions` غیرفعال، پوشه جدید `extension` را Load unpacked و تب BilitFast را Reload کنید.
- در همان پروفایل مرورگر، یک‌بار در تب رسمی `https://safirrail.ir/etrain/index.php` وارد حساب شوید و اتصال مستقیم افزونه را انجام دهید.
- به تب BilitFast برگردید و «انتخاب و تأیید ربات» را بزنید. باید صفحه رسمی در **همان تب** باز شود. در صورت شکست، وضعیت صفحه و پنل/خطای افزونه را بررسی کنید.

**محدودیت‌ها:** عملکرد واقعی تحت کنترل سایت رسمی است. ورود نامعتبر، محدودیت WebView، ظرفیت منقضی‌شده یا تغییر فرم رسمی ممکن است ادامه را ناموفق کند. هیچ وعده‌ای برای عبور خودکار از CAPTCHA یا پرداخت داده نمی‌شود. این اصلاح فقط مسیر شروع را از آزمون غیرضروری سروری مستقل می‌کند.
