# BilitFast Web 3.13.0 — نصب مستقل با یک حساب مالک

این نسخه از 3.12.2 ساخته شده است. موتور جستجو، افزونه، نمایش رزرو در تب جدید، تأیید انسانی ARCaptcha و درج مسافر تغییر نکرده‌اند.

## قرارداد محصول

- هر نصب مستقل (`installation.json`) یک دوره آزمایشی ۷۲ساعته یا یک مجوز دائمی امضاشده دارد.
- **یک حساب مالک** (`admin`) برای همان نصب مجاز است. ثبت‌نام عمومی، ساخت حساب دوم و مدیریت کاربران قدیمی از API حذف/مسدود شده‌اند. نیازی به نقش tester/user یا سهمیه مجزای کاربر نیست.
- ورود با رمز لازم است؛ حساب مالک می‌تواند گذرواژه را عوض کند. تنها **آخرین نشست ورود فعال** است؛ ورود از دستگاه دیگر نشست قبلی را باطل می‌کند. این روش جایگزین تشخیص سخت‌افزاری نیست.
- از **نسخه 3.13.1** شناسه تصادفی نصب علاوه بر امضای فروشنده به هش هویت سیستم‌عامل میزبان متصل می‌شود. کپی `installation.json` به میزبان دیگر دیگر معتبر نیست؛ در Docker روی سرور Linux هویت میزبان از mount فقط‌خواندنی `/etc/machine-id` خوانده می‌شود. این اقدام **ضد‌دستکاری مطلق نیست**: مالک root می‌تواند نرم‌افزار یا شناسه ماشین را جعل کند و Docker Desktop ویندوز با این Compose به‌طور کامل پشتیبانی نشده است.
- استفاده از برنامه از یک مرورگر مشتری با HTTPS، روی سرور متعلق به مشتری انجام می‌شود؛ نسخه وب معمولی «نصب محلی روی همان کامپیوتر» نیست.

## راه‌اندازی تازه

1. `node scripts/setup-selfhost.js example.com` فقط یک‌بار، روی سیستم/هاست مشتری؛ فایل `.env`، کلید اصلی و راز راه‌اندازی را در محل امن نگهداری کنید.
2. `docker compose -f compose.selfhost.yml up -d --build`؛ برنامه با `BILITFAST_SINGLE_USER=1` اجرا می‌شود.
3. `https://example.com/admin.html` را باز کنید و با راز راه‌اندازی، یک حساب مالک با گذرواژه قوی بسازید.
4. بعد از ورود، در `trial.html` شناسه نصب و وضعیت دوره آزمایشی یا کد فعال‌سازی را ببینید.
5. الگوهای مسافر با WebCrypto در همان پروفایل مرورگر و همان مبدأ `https://example.com` باقی می‌مانند. پاک‌کردن داده‌های سایت یا تعویض مرورگر، آن‌ها را از بین می‌برد؛ نسخه فعلی همگام‌سازی بین سیستم‌ها ندارد.

**برای توسعه محلی** `npm run preview:web` سرویس HTTP در `127.0.0.1:3000` را اجرا می‌کند. این حالت تولید نیست و ممکن است کلیدهای رمزنگاری موقت داشته باشد؛ برای تست ذخیره پایدار و لایسنس از تست production استفاده کنید.

## مهاجرت از نصب‌های قبلی

- پیش از هر کار از **تمام `/data` و فایل `.env` با هم** پشتیبان رمزنگاری‌شده بگیرید. کلید خصوصی فروشنده نباید روی هاست مشتری قرار بگیرد.
- اگر دیتابیس پیشین **بدون حساب** باشد، ساخت مالک مجاز است.
- اگر دقیقاً **یک حساب admin** موجود باشد، پس از فعال‌سازی نسخه جدید همان حساب مالک می‌ماند. نشست‌های ورود پیشین اعتبار ندارند؛ مجدداً با رمز وارد شوید.
- رکورد نصب قدیمی v1 فقط با کد مهاجرت Ed25519 امضاشده فروشنده (`BFM1`)، که به شناسه نصب و هش میزبان اختصاص داده شده، مهاجرت می‌کند. `BILITFAST_MIGRATE_LEGACY_INSTALLATION=1` به‌تنهایی مجوز نیست. برای دستورهای دقیق و صدور کد به `docs/DELIVERY-3.13.1-FA.md` مراجعه کنید. فروشنده باید مالکیت مشتری را تأیید کند.
- اگر بیش از یک حساب یا یک حساب غیر-admin موجود باشد، سرویس تولید عمداً راه‌اندازی نمی‌شود و هیچ داده‌ای خودکار حذف نمی‌شود. مهاجرت باید پس از تهیه پشتیبان و تعیین مالک انجام شود؛ حساب‌های قدیمی، رزروها و داده‌های مسافر را کورکورانه پاک نکنید.
- اولین اجرای production، `data/db.json` متنی نسخه قدیمی را با نوشتن اتمیک به قالب **AES-256-GCM** منتقل می‌کند. نسخه پشتیبان قدیمی ممکن است همچنان متن ساده باشد؛ آن را امن نگه دارید.
- اگر `BILITFAST_MASTER_KEY` گم شود، بازیابی دیتابیس رمزنگاری‌شده بدون نسخه پشتیبان کلید ممکن نیست. کلید اصلی را پس از فعال‌سازی تغییر ندهید.
- فقط **یک پردازش/کانتینر** همزمان روی فایل دیتابیس کار کند. ذخیره‌ساز KV مشترک در حالت single-owner فعلی پشتیبانی نمی‌شود.

## کنترل‌های امنیتی

- داده‌های جدول کاربران، کوکی‌های قدیمی، رزروها و اطلاعات شخصی در فایل دیتابیس نصب تولید به‌صورت رمزنگاری‌شده ذخیره می‌شوند؛ در حافظه سرویس برای انجام عملیات باز می‌شوند.
- ورود دوم نشست قبلی را باطل می‌کند. خروج یا تغییر گذرواژه، نشست را باطل می‌کند.
- مرورگر بدون WebCrypto/IndexedDB معتبر **نباید اطلاعات هویتی را به متن ساده ذخیره کند**؛ از HTTPS یا localhost استفاده کنید و در صورت خطای ذخیره پیغام مربوطه را بررسی کنید.
- خطای نوشتن فایل دیتابیس دیگر موفقیت جعلی برنمی‌گرداند.
- همچنان از دامنه معتبر HTTPS، دسترسی محدود به فایل داده، پشتیبان رمزنگاری‌شده و به‌روزرسانی امنیتی استفاده کنید. قفل هویت میزبان در برابر کپی ساده فعال است ولی صدور/لغو آنلاین لایسنس و حفاظت در برابر دستکاری root هنوز وجود ندارد.

## تست

```bash
npm ci
npm run test:single-owner
npm run test:passenger-profiles
npm test
node scripts/selfhost-smoke.js
```

**محدودیت تأیید:** این آزمون‌ها رزرو زنده، حل کپچا یا پرداخت را اجرا نمی‌کنند. برای فروش نهایی، آزمایش با حساب واقعی و درگاه رسمی هنوز ضروری است.
