# موتور OCR بازطراحی‌شده (ocr-engine/1.0)

این سند معماری، وابستگی‌ها و قراردادهای موتور جدید حل کپچا را توضیح می‌دهد.
اعداد اندازه‌گیری‌شده در [`BENCHMARK-REPORT.md`](./BENCHMARK-REPORT.md) آمده‌اند.

## ۱) معماری و گراف وابستگی‌ها

### وابستگی‌های کلیدی
- `lib/captcha.js::solveCaptcha` → موتور جدید را به‌عنوان **نامزد اول** امتحان
  می‌کند (`use_ocr_engine` در config) و در هر خطا بی‌صدا به مسیرهای قدیمی
  (مدل الفبایی/نمونه‌محور + تِسِرَکت) فال‌بک می‌شود. امضای تابع و جریان رزرو
  (`lib/reserve.js`) هیچ تغییری نکرده است.
- `scripts/benchmark.js` تنها نقطه‌ای است که آموزش، کالیبراسیون و ارزیابی را
  با پروتکل بدون نشت اجرا می‌کند.

## ۲) پروتکل بدون نشت (بنچمارک)

1. تفکیک **سطح-تصویر** با بذر ثابت (`splitByIdentity`): train/val/cal/test.
2. آموزش فقط روی train (+ افزون‌سازی هندسی ملایم، توقف زودهنگام روی دقت
   اعتبارسنجی، کاهش نرخ یادگیری، دراپ‌اوت).
3. کالیبراسیون دما **فقط** روی cal (`fitTemperature`)؛ آستانهٔ تصمیم هم فقط
   روی cal (`pickThreshold`).
4. گزارش نهایی فقط روی test؛ ECE تست بدون هیچ برازشی محاسبه می‌شود.
5. بنچمارک مصنوعی با بذرهای مستقل آموزش/تست برای سنجش تعمیم واقعی و کیفیت
   قطعه‌بندیِ مستقل از تشخیص (شمارش + IoU در برابر جعبه‌های مرجع).

اگر آموزش ≈۱۰۰٪ و اعتبارسنجی به‌وضوح پایین‌تر باشد، اسکریپت صریحاً
«بیش‌برازش» اعلام می‌کند.

## ۳) ماژول‌ها

| فایل | مسئولیت |
|---|---|
| `lib/ocr/config.js` | اسکیمای تایپ‌سیف تنظیمات + اعتبارسنجی با پیام خطای واضح |
| `lib/ocr/preprocess.js` | مراحل پیش‌پردازش خالص و ترکیب‌پذیر؛ مورفولوژی محافظ |
| `lib/ocr/polarity.js` | تشخیص قطبیت با ۵ هیوریستیک + اطمینان |
| `lib/ocr/segment.js` | قطعه‌بندی چندعاملی + ارزیابی مستقل کیفیت |
| `lib/ocr/recognizer.js` | مدل‌های تشخیص با اعتبارسنجی ورودی و کاراکترست کانفیگی |
| `lib/ocr/calibration.js` | دما، ECE، نمودار اتکاپذیری |
| `lib/ocr/confidence.js` | تفکیک اطمینان کاراکتر/توالی + انتخاب آستانه |
| `lib/ocr/ensemble.js` | رأی وزن‌دار کالیبره + همبستگی خطا (Q) + سهم مدل‌ها |
| `lib/ocr/metrics.js` | CharAcc, SeqAcc, P/R/F1, CER, ماتریس درهم‌ریختگی |
| `lib/ocr/split.js` | تفکیک بذردار بدون نشت + `assertNoLeakage` |
| `lib/ocr/logging.js` | لاگ هر استنتاج (نسخه پایپ‌لاین/مدل، اطمینان‌ها، تأخیر، دلیل شکست) |
| `lib/ocr/failure-analysis.js` | دسته‌بندی خطاها: قطعه‌بندی/قطبیت/پیش‌پردازش/تشخیص/اطمینان/طول |
| `lib/ocr/engine.js` | ارکستراسیون مسیر کامل + خروجی ساخت‌یافته |
| `lib/synthfont.js` | فونت بیت‌مپ ۵×۷ (۶۲ گلیف، سه سبک) |
| `lib/synthgen.js` | تولیدکنندهٔ بذردار با کنترل فونت/فاصله/چرخش/نویز/کنتراست/هم‌پوشانی |
| `train/ocr-train.js` | آموزش با پروتکل تفکیک + تنظیم‌کننده‌ها |
| `scripts/benchmark.js` | اجرای کامل پروتکل + تولید گزارش/JSON |

## ۴) اجرا

```bash
npm test                     # همهٔ تست‌ها (۱۵ سوئیت)
npm run test:ocr             # فقط تست‌های موتور جدید
npm run benchmark:quick      # بنچمارک سریع (~۱٫۵ دقیقه)
npm run benchmark            # بنچمارک کامل (~۴ دقیقه) → docs/BENCHMARK-REPORT.md
node scripts/eval-solve.js   # بنچمارک استاندارد قدیمی (حافظه‌سنجی؛ فقط سازگاری)
```

## ۵) نقاط شکست شناخته‌شده و وضعیتشان

| نقطه شکست قدیمی | وضعیت جدید |
|---|---|
| نشت کامل: آموزش و تست یکسان (۱۰۰٪ کاذب) | حذف شد — تفکیک ۴بخشی سطح-تصویر |
| برازش دمای کالیبراسیون روی خود تست | دما فقط روی cal |
| «بزرگ‌ترین مؤلفه‌ها = کاراکتر» | امتیازدهی چندعاملی + جستجوی چیدمان + ادغام/شکافت |
| قطبیت با یک آستانه روی میانگین حاشیه | ۵ هیوریستیک + رأی‌گیری + اطمینان |
| پیش‌پردازش یکپارچه و غیرقابل ارزیابی | مراحل مستقل + جدول ابلیشن خودکار |
| مورفولوژی تهاجمی روی استروک‌های نازک | فرسایش فقط اگر عرض ضربهٔ غالب ≥۵ پیکسل |
| اطمینان توالی = میانگین ساده | کمینه/میانگین/توالی جدا + فرمول مستند |
| کاراکترست هاردکد در چند فایل | فقط از کانفیگ (`charsetFor`) |
| حافظهٔ نمونه‌محور بی‌قید در بنچمارک | k-NN در بنچمارک فقط بردارهای train می‌گیرد |
| بدون لاگ استنتاج | لاگ ساخت‌یافته + JSONL |

## ۶) محدودیت‌های صادقانه

- ۴۹ تصویر واقعی برای ۴۱ کلاس بسیار کم است؛ دقت کاراکتری ندیده ~۴۰٪
  (بازهٔ ۳۴-۴۶٪ بین اجراها) ذاتیِ کمبود داده است، نه ضعف پایپ‌لاین.
- حروف بین رندرهای مختلف تعمیم نمی‌دهند (اعوجاج هر کپچا متفاوت است)؛
  k-NN فقط روی شکل‌های دیده‌شده کار می‌کند و در بنچمارک عمداً محدود به
  بردارهای آموزش است.
- مسیر تولید همچنان از همهٔ نمونه‌های تأییدشدهٔ ذخیره‌شده استفاده می‌کند
  (رفتار درست برای زمان اجرا)؛ صداقت آماری مربوط به بنچمارک است.
