# BilitFast Web 3.13.3 — تفکیک نتیجه جستجو و اعتبار نشست

## مشکل نسخه قبل
در نسخه 3.13.2 متن «۲۴ قطار یافت شد اما موجودی همه صفر است... یا نشست ورود منقضی شده است» از روی تعداد ردیف‌ها و جستجوی `[1-9]` در متن خام ساخته می‌شد؛ ارقام فارسی و موجودی ناخوانا ممکن بود صفر تلقی شوند. داشتن PHPSESSID به‌تنهایی ورود معتبر را اثبات نمی‌کند.

## اصلاحات
- شمارش «ردیف‌های نتیجه» به‌جای ادعای شمار قطارهای قابل رزرو.
- تشخیص ارقام فارسی، عربی و انگلیسی و نگهداری `capacity: null` برای داده ناخوانا.
- سه وضعیت مستقل جستجو: `no_capacity` (صفر/ناکافی با شاهد)، `no_match` (قطار انتخابی دیده نشد)، `availability_unverified` (ظرفیت قابل استخراج نیست).
- انقضای نشست فقط هنگام مشاهده شواهد ورود مجدد در پاسخ/URL رسمی گزارش می‌شود، نه به خاطر ظرفیت صفر.
- شمارش ظرفیت فقط برای ردیف‌هایی که با شماره قطار انتخابی مطابق‌اند.
- هر سه وضعیت منفی/نامعلوم با فاصله معمول ادامه پیدا می‌کنند و باعث افزایش backoff خطای شبکه نمی‌شوند.
- نوسازی نسخه cache سرویس‌ورکر به 3.13.3 تا صفحه قدیمی به کاربر نمایش داده نشود.
- خروجی تشخیصی از سایت قبل از قرارگرفتن در HTML escape می‌شود.

## نحوه نصب/تست
1. از اطلاعات نصب کنونی شامل تنظیمات لایسنس و پایگاه داده نسخه پشتیبان بگیرید. آن‌ها را با فایل‌های بسته تازه جایگزین نکنید.
2. سرور قبلی را متوقف و فایل‌های سورس 3.13.3 را در پوشه جدید استخراج کنید.
3. در پوشه `BilitFast-Web-SelfHosted`: `npm ci`، سپس `npm test`، `npm run audit:security`، `npm run test:enterprise`، `npm run start:dev`.
4. مرورگر را با Ctrl+Shift+R تازه کنید. اگر PWA نصب شده، پس از بروزرسانی سرویس‌ورکر بارگذاری مجدد کنید. افزونه مرورگر را Reload کنید.
5. آزمایش دستی با نشست واقعی صفیرریل و سناریوهای ظرفیت/بدون ظرفیت همچنان ضروری است.

## محدودیت‌های تحویل
`npm run check:delivery` بدون کلید عمومی اصلی فروشنده (`config/license-public.pem`) رد می‌شود. کلید خصوصی فروشنده را داخل سورس مشتری قرار ندهید. شبیه‌سازی آزمایشگاهیِ HTML صفیرریل، جایگزین آزمون عملیاتی رزرو در سایت نیست. وابستگی‌ها در محیط ممیزی نصب تمیز و اسکن امنیتی مستقل نشده‌اند.
