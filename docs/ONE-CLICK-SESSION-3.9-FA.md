# BilitFast Web 3.9.0 — اتصال یک‌کلیکی و رفع انتظار بی‌پایان

## مشکل قبلی
صفحه `login.html` پس از دریافت کوکی در `poll` ابتدا درخواست `verify` را به
سرور واسط می‌فرستاد؛ این درخواست نیازمند ارتباط خارجی با SafirRail بود و
می‌توانست کند یا معلق شود. در این فاصله نه `setCookies` اجرا می‌شد و نه
`ack`، لذا رابط همان «منتظر پاسخ هستیم» باقی می‌ماند و کاربر دوباره کد وارد
می‌کرد. کپی دستی کد به popup هم احتمال اشتباه را بالا می‌برد.

## رفتار جدید
1. پس از بازشدن صفحه اتصال BilitFast، یک کد موقت با nonce اختصاصی همان تب
   ساخته می‌شود. **nonce به افزونه داده نمی‌شود**.
2. کاربر در سایت رسمی SafirRail با حساب خودش وارد می‌شود و سپس از تب
   BilitFast روی آیکون افزونه و «اتصال امن با یک کلیک» می‌زند.
3. افزونه با تأیید دامنه مقصد و مجوز مرورگر، کد را از DOM همان صفحه BilitFast
   می‌خواند؛ کد دیگر تایپ یا Paste نمی‌شود.
4. افزونه **فقط پس از همین اقدام صریح کاربر** کوکی‌های SafirRail را به سرور
   **همان نصب انتخاب‌شده** ارسال می‌کند.
5. صفحه BilitFast کوکی تحویل‌شده را فوراً در ذخیره‌سازی تب قرار می‌دهد و
   سپس ACK می‌فرستد. تأیید آنلاین صفیر ریل مسیر دریافت را مسدود نمی‌کند.
6. کاربر پیام «نشست ذخیره شد؛ اعتبار فقط در مرحله رزرو رسمی تعیین می‌شود»
   می‌بیند. کد بازیابی و دستور ساخت دوباره کد در بخش پیشرفته قرار دارند.

## خطاهای متمایز
- کد پیدا نشد / منقضی شد: صفحه اتصال را رفرش کنید؛ فقط در همان تب افزونه را باز کنید.
- مجوز دامنه رد شد: باید دقیقاً همان آدرس HTTPS یا 127.0.0.1:3000 مجاز شود.
- کوکی PHPSESSID وجود ندارد: داخل تب رسمی به حساب رزرو وارد شوید، نه مهمان.
- ذخیره‌سازی مسدود است: هیچ ACK زده نمی‌شود و کد تا انقضای رکورد قابل بازیابی است.
- سه خطای متوالی ارتباط با API: انتظار متوقف و پیام خطای شبکه نشان داده می‌شود.
- کوکی ذخیره شد ولی رزرو رد شد: انتقال موفق به معنی ورود معتبر نیست؛
  مسیر رسمی در مرورگر باید پذیرفته شود. سرور خارجی ممکن است IP/UA متفاوت داشته باشد.

## تست‌ها
از پوشه اصلی: `npm ci`، `npm run test:one-click`، `npm run test:web-extension`، `npm test`، `npm run preview:web`.
افزونه را در `chrome://extensions` از پوشه `extension` با **Load unpacked**
نسخه 3.9.0 بارگذاری کنید؛ سایر نسخه‌های BilitFast را خاموش کنید.

## مرزهای امنیتی
- هرگز مقادیر Cookie/PHPSESSID، کد ورود، گذرواژه یا اطلاعات کارت را برای پشتیبانی ارسال نکنید.
- دامنه مشتری باید HTTPS باشد؛ HTTP فقط `127.0.0.1:3000`/`localhost:3000` برای توسعه است.
- سامانه نمی‌تواند پذیرش یا زمان انقضای کوکی توسط SafirRail را تضمین کند.
- ARCaptcha در مبدأ رسمی اجرا و **فقط به‌دست انسان** تأیید می‌شود؛ هیچ توکن یا
  کلیک روی ویجت دست‌کاری/شبیه‌سازی نمی‌شود.
- برای راهکاری که انتقال کوکی بین دو مبدأ را به‌طور کامل حذف کند، باید
  جستجو و رزرو صرفاً first-party در همان مرورگر یا از طریق API رسمی انجام شود؛
  موتور فعلی جستجوی سروری برای برخی پاسخ‌های واردشده هنوز به کوکی نیاز دارد.
