# BilitFast Web Self-Hosted — راهنمای فروش و نصب مستقل

## این نسخه دقیقاً چیست؟

این بسته، نسخه **تحت وب با استقرار مستقل هر مشتری** است؛ SaaS مشترک فروشنده نیست. هر آژانس داده، حساب‌ها، دامنه، Docker volume و کلیدهای امنیتی **مختص خودش** را دارد. کاربران آژانس فقط نشانی HTTPS را در Chrome/Edge باز می‌کنند و برای خود برنامه به نصب Node.js یا Electron نیاز ندارند.

تحت وب بودن به معنی حذف میزبان نیست: آژانس یک **VPS / سرور تحت مدیریت خودش** با Docker و یک دامنه دارد. بدون میزبان، پایش دائمی سمت سرور و API رزرو امکان‌پذیر نیست.

## وضعیت عملکرد

- ✅ داشبورد وب و API فعلی بدون Electron، راه‌اندازی از `selfhost-server.js`
- ✅ یک استقرار، یک شناسه نصب (۳۲ کاراکتری)، آزمایش ۷۲ساعته با تاریخ پایدار روی Docker volume
- ✅ کد Ed25519 امضاشده فروشنده، فعال‌سازی دائمی بدون مراجعه به سرور فروشنده؛ کلید خصوصی فروشنده نباید داخل ZIP مشتری باشد
- ✅ ایجاد مدیر اولیه با راز امن و احراز هویت حساب کاربران
- ✅ افزونه مرورگر: آدرس HTTPS نصب مشتری با اجازه صریح؛ دیگر جستجوی پورت‌های ۳۰۰۰/۳۲۱۰ و انتقال اتفاقی به نسخه قدیمی وجود ندارد
- ✅ یک فایل Compose برای وب‌سرور + Caddy و گواهی HTTPS
- ⚠️ عملکرد واقعی انتقال نشست، جستجو، ARCaptcha و رزرو با سایت ثالث آزمایش نشده؛ خصوصاً امکان محدودیت IP میزبان و نشست وابسته به مرورگر وجود دارد.
- ⚠️ اگر سایت اصلی ARCaptcha را الزام کند، کاربر آن را **در سایت رسمی** خودش تأیید می‌کند؛ صفحه یک دامنه دیگر حق برداشت/تأیید خودکار توکن را ندارد.
- ⚠️ پایگاه داده کنونی JSON مناسب **استقرار تک‌پردازشی و حجم محدود** است، نه Enterprise مقیاس بالا. برای فروش سازمانی پرترافیک باید به PostgreSQL تراکنشی مهاجرت کند.
- ⚠️ روی میزبان کاملاً تحت کنترل خریدار، **لایسنس آفلاین ضد‌دستکاری مطلق نیست**. مشتری می‌تواند فایل برنامه یا ساعت/دیتا را دستکاری کند؛ بدون سرور اعتبارسنجی فروشنده تضمین ضدکپی وجود ندارد. قرارداد، پشتیبانی و فعال‌سازی مجدد کنترل‌شده مکمل‌اند.

## مراحل روی هاست مشتری (Linux VPS)

شرایط اولیه: IP عمومی، دامنه `agency.example.com` که DNS آن به VPS اشاره می‌کند، Docker Engine و Docker Compose Plugin؛ پورت‌های ۸۰ و ۴۴۳ باز، زمان سیستم NTP تنظیم‌شده. برنامه نباید روی سرور فروشنده میزبانی شود.

۱. ZIP را روی سرور متعلق به آژانس باز کنید. از پوشه پروژه، فایل `.env` را **فقط یک بار** تولید کنید؛ بدون نصب Node.js روی میزبان (Node داخل کانتینر موقت اجرا می‌شود):

```bash
docker run --rm -v "$PWD:/work" -w /work node:22-alpine \
  node scripts/setup-selfhost.js agency.example.com
```

۲. فروشنده باید قبلاً `config/license-public.pem` متناظر با کلید خصوصی خودش را در بسته قرار داده باشد. **کلید خصوصی هرگز همراه مشتری نیست.** برای امکان آزمایش ۷۲ساعته، در صورت نبود کلید عمومی هم برنامه شروع می‌شود؛ اما صدور کد دائمی تا زمان نصب کلید عمومی ممکن نخواهد بود.

۳. اجرا:

```bash
docker compose -f compose.selfhost.yml up -d --build
docker compose -f compose.selfhost.yml ps
docker compose -f compose.selfhost.yml logs --tail=100 app
```

۴. در مرورگر **HTTPS** به `https://agency.example.com/admin.html` بروید. رمز bootstrap در `.env` روی سرور مشتری، با نام `BILITFAST_ADMIN_BOOTSTRAP_SECRET` است. مدیر اولیه را ایجاد کنید. سپس بقیه کارکنان از طریق پنل ادمین ساخته می‌شوند. راز bootstrap را پس از ایجاد مدیر از محیط اجرایی حذف/چرخش دهید؛ **هیچ‌گاه در تیکت پشتیبانی منتشر نکنید**.

۵. در `https://agency.example.com/trial.html`، شناسه نصب را ببینید. دوره آزمایشی **از اولین اجرای سرور** شروع می‌شود، نه اولین ورود هر کارمند.

۶. بعد از خرید، فروشنده فقط با کلید خصوصی نگهداری‌شده روی **کامپیوتر خودش** کد را صادر می‌کند:

```bash
# فقط سیستم فروشنده؛ یک بار و با نگهداری پشتیبان امن:
node scripts/license-admin.js init
# شناسه از صفحه trial همان آژانس:
node scripts/license-admin.js issue 0123456789abcdef0123456789abcdef --days 30
```

`--days 30` مهلت **واردکردن کد** است؛ پس از واردشدن معتبر، مجوز آن نصب دائمی است. مدیر آژانس پس از ورود، کد کامل با پیشوند `BF1.` را در صفحه `trial.html` وارد می‌کند. همه کارکنان همان نصب از آن مجوز استفاده می‌کنند.

۷. افزونه `extension` نسخه وب در Chrome/Edge با اجازه کاربر نصب می‌شود. هنگام اتصال، کاربر آدرس HTTPS **همان آژانس** را وارد و کد شش‌رقمی را از `login.html` کپی می‌کند. کوکی نشست از مرورگر **به سرور آژانس** منتقل می‌شود؛ این ارتباط داده حساس است، پس تنها به دامنه مورد اعتماد خود آژانس اجازه بدهید. **هیچ کوکی‌ای برای پشتیبانی ارسال نشود.** عرضه عمومی افزونه از فروشگاه Chrome/Edge هنوز انجام نشده و برای تجربه «بدون تنظیم دستی» لازم است.

## حفاظت از داده و پشتیبان‌گیری

- از Docker volume `bilitfast_data` و فایل `.env` هر نصب به‌شکل رمزگذاری‌شده پشتیبان بگیرید. **هر دو با هم لازم‌اند:** از دست‌رفتن master key باعث غیرقابل‌خواندن‌شدن داده‌های رمز‌شده می‌شود.
- فایل `installation.json` داخل volume نباید حذف یا بازنویسی شود؛ با حذف آن، شناسه نصب و مجوز قبلی از بین می‌رود (و در سیستم مستقلِ تحت کنترل مشتری ممکن است آزمایش تازه ساخته شود).
- سرویس را روی یک پردازش/نمونه اجرا کنید؛ این دیتابیس JSON برای چند Replica یا چند کانتینر app همزمان امن نیست.
- پورت ۳۰۰۰ برنامه از اینترنت باز نشود؛ فقط reverse proxy با HTTPS به آن دسترسی دارد.
- SSL باید معتبر باشد و از اتصال افزونه با HTTP روی اینترنت استفاده نکنید.

## آزمایش سریع بدون رزرو/پرداخت واقعی

```bash
node test/selfhost-web.test.js
node scripts/selfhost-smoke.js
node test/extension-endpoint-discovery.test.js
```

این تست‌ها روی نسخه ZIP سورس اجرا شده‌اند. تست کامل `npm ci && npm test` باید در محیط متصل به npm و روی سرور مشتری اجرا شود؛ اجرای واقعی سایت اصلی نیازمند حساب مجاز و بررسی شرایط استفاده است.

## کارهای باقی‌مانده قبل از فروش گسترده

۱. تست زنده Chrome/Edge، انتقال نشست HTTPS و اعتبار فرم رزرو در IP میزبان مشتری با مجوز صاحب حساب.
۲. تعیین راه رسمی اتصال سفیر ریل؛ اگر نشست به IP یا مرورگر گره خورده باشد، ارسال کوکی به سرور VPS همیشه کار نمی‌کند.
۳. انتقال پایگاه داده JSON به PostgreSQL و پوشش تراکنش‌ها، بکاپ/بازیابی، تست فشار و تست همزمانی.
۴. رفع موارد گزارش‌شده در `npm audit --omit=dev`، hardening نشست و CSRF/CORS، و مرور امنیت حرفه‌ای.
۵. انتشار افزونه تأییدشده در فروشگاه مرورگر، مستندات خدمات/حریم خصوصی و قرارداد مجوز.
۶. طراحی سازوکار بازیابی و انتقال مجوز در صورت تغییر سرور مشتری؛ مجوز فعلی به شناسه volume داده بسته می‌شود.

**فروش این بسته در وضعیت حاضر تنها با عنوان «نسخه آزمایشی وب Self-Hosted برای تست مشتری» دقیق است؛ نه محصول Enterprise کاملاً تأییدشده برای رزرو واقعی.**
