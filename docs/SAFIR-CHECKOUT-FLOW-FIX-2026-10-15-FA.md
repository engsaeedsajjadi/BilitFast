# اصلاح مرحله اطلاعات مسافر → تأیید خرید → درگاه (BilitFast Web 3.4.1)

## خطای بازتولیدشده در سورس

در نسخه 3.4.0، افزونه بعد از تکمیل اطلاعات مسافر از `form.requestSubmit()` استفاده می‌کرد. این API رویداد **کلیک** دکمه را اجرا نمی‌کند. اگر دکمه رسمی سایت از `onclick="chkForm()"` استفاده کند (مطابق تحلیل موجود در `lib/reserve.js`)، همان تابع مقصد ارسال فرم را به `VerifyTck.php` تغییر می‌دهد. در نتیجه نسخه قبل می‌توانست فرم را بدون اجرای تابع اصلی به `TresV.php` بازفرستد.

همچنین نمایش آدرس `TresV.php` بعد از حل ARCaptcha لزوماً خطا نیست: در HTML ارائه‌شده، action فرم ARCaptcha همین مسیر است. تشخیص خطا به **محتوای صفحه و مرحله واقعی** وابسته است، نه تنها آدرس.

## اصلاح

- ماژول `extension/checkout-flow.js` فقط فرم POST رسمی روی `https://safirrail.ir` را می‌پذیرد و دکمه رسمی `chkForm()` را **با کلیک روی خود کنترل سایت** اجرا می‌کند؛ نه `form.submit()`، تغییر دستی مقصد، یا ساخت توکن جدید.
- اگر فرم از قبل به `VerifyTck.php` اشاره کند، دکمه رسمی ارسال استفاده می‌شود.
- اگر چنین کنترل یا action رسمی وجود نداشته باشد، ارسال خودکار متوقف و از کاربر خواسته می‌شود دکمه رسمی را دستی بزند.
- اطلاعات مسافر تا زمانی که پاسخ تأیید خرید قابل‌شناسایی باشد نگهداری می‌شود؛ بعد از تشخیص تأیید، پاک می‌شود. در صورت رفتن همان تب به `pec.shaparak.ir/NewIPG/`، افزونه صرفاً بر اساس دامنه و مسیر، وضعیت را ثبت می‌کند و اطلاعات موقت را پاک می‌کند؛ پارامتر Token خوانده یا ذخیره نمی‌شود. شناسایی تغییر آدرس بانکی ممکن است به محدودیت مجوزهای Chrome وابسته باشد.
- **هیچ کلیک یا جعل توکن ARCaptcha انجام نمی‌شود.** کاربر باید تأیید ضدربات را شخصاً در صفحه رسمی انجام دهد.
- مرحله «تأیید خرید» را افزونه فقط با شواهد محتوای صفحه نشان می‌دهد؛ صرف `VerifyTck.php` تأیید پرداخت نیست.
- این وصله صفحه خرید سفیر ریل را بازنویسی نمی‌کند، درگاه ثابت اضافه نمی‌کند و پرداخت بانکی را خودکار انجام نمی‌دهد.

## اجرای تست در Windows PowerShell

در پوشه `BilitFast-Web-SelfHosted`:

```powershell
npm ci
npm run test:checkout
npm test
npm run preview:web
```

افزونه قبلی را در `chrome://extensions` غیرفعال و پوشه `extension` نسخه **3.4.1** را Load unpacked کنید. از آدرس محلی `http://127.0.0.1:3000` برای تست استفاده کنید. در وب‌اپلیکیشن، اطلاعات قطار و مسافر را وارد کنید و روی شروع رزرو در افزونه بزنید.

### مشاهده و ثبت نتیجه بدون اطلاعات حساس

۱. در تب رسمی سفیر ریل، ARCaptcha را خودتان تأیید کنید.

۲. مطمئن شوید اطلاعات مسافر درست درج شده است. با رضایت قبلی، افزونه می‌تواند کنترل رسمی فرم را برای رفتن به مرحله بعد اجرا کند.

۳. انتظار می‌رود **محتوای صفحه تأیید خرید** ظاهر شود. پیش از تأیید نهایی، نام مسافر، قطار، تاریخ و مبلغ را خودتان بررسی کنید.

۴. فقط پس از تأیید سایت، انتقال به درگاه معتبر باید توسط سایت انجام شود. از یک URL بانکیِ قدیمی یا توکن نمونه استفاده نکنید.

اگر همچنان در `TresV.php` هستید، برای عیب‌یابی فقط این اطلاعات **غیرحساس** را ثبت کنید: pathname صفحه، آیا فیلدهای `pid0` و `fn0` دیده می‌شوند، آیا دکمه‌ای با `onclick` شامل `chkForm` وجود دارد، و عنوان پیام خطای قابل‌مشاهده (بدون کد ملی و توکن). **HTML خام، Cookie، مقدار `arcaptcha-token`، URL دارای `Token=`، کد ملی و رمز عبور را ارسال نکنید.**

## محدودیت هنوز حل‌نشده

در مدل وب self-hosted نمی‌توان ویجت ARCaptcha را صرفاً با کوکی به دامنه BilitFast منتقل کرد. ویجت واقعی روی مبدأ رسمی سایت اجرا می‌شود و نمای BilitFast به‌صورت پنل کناری همان مرورگر باقی می‌ماند. اجرای کامل و تأیید نهایی در سایت واقعی و روی حساب مجاز مشتری باید انجام شود.
